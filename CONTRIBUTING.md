# Contributing to Hack SP

Thanks for wanting to help build Hack SP.

Hack SP is built by students, and we want contributing to our projects to feel approachable whether you've been coding for years or this is your first open source contribution.

## Before you start

If you're fixing a small bug, feel free to open a pull request directly.

For larger changes or new ideas, opening an issue first is usually a good idea so we can discuss the direction together.

## Making a change

1. Fork the repository.
2. Create a branch for your change.
3. Make your changes.
4. Test everything locally.
5. Open a pull request.

Keep branches simple and descriptive:

```bash
feat/new-page
fix/mobile-navbar
docs/update-readme
````

## Commits

We prefer short and clear commit messages.

```text
feat: add event page
fix: improve mobile navigation
docs: update setup instructions
```

They don't need to be perfect. They just need to explain what changed.

## Pull requests

A good pull request tells us:

* what changed;
* why it changed;
* how it was tested;
* and, for visual changes, what it looks like.

Small pull requests are usually easier to review than very large ones.

## Most importantly

Don't be afraid to contribute because you think your code isn't good enough.

Open source is also a place to learn.

If something can be improved, we'll figure it out together.

**Build things. Learn things. Help others build too.**
